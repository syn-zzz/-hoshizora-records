# ほしぞらレコード デモサイト 制作計画書（v2）

更新日：2026-11-06

## 0. 前提

* 目的：はじめてのWebサイト制作の練習を兼ねて、ほしぞらレコードへのリニューアル提案用デモを作る。完成したら営業に行く。案件を獲得したらヒアリングして細かく修正する。
* 費用：無料で作る（有料テーマ・有料プラグイン・サーバー代なし）。
* 仕様書：DESIGN.md（見た目）と CONTENTS.md（文章と構成）。AIへの指示では毎回この2つを最優先にする。
* デモの扱い：店主さんの了承を得る前なので一般公開しない。見せるときはパスワード付きにする。フッターにデモ表記を入れる。

## 1. 決定事項

| 項目 | 決定 | 理由 |
| --- | --- | --- |
| WordPressのテーマ | 自作テーマ（HTML/CSSから変換） | 無料。テーマの仕組みも学べる。SWELLは有料なので使わない |
| 開発環境 | Local（パソコン上でWordPressを動かす無料アプリ）＋ Git | サーバー代がかからない。AIが壊しても戻せる |
| デモの見せ方 | LocalのLive Links（ユーザー名・パスワード付きの一時URL）か、ノートPC・タブレットで直接見せる | サーバー代0円。一般公開されない |
| 本番サーバー・ドメイン | 受注後に契約（店主さんの費用） | HTTPS（無料SSL）はこのとき設定する |
| 画像 | フリー素材（Pexels・Pixabay）を手動でダウンロード → WebPに変換 → メディアライブラリに登録。外部への直接リンクはしない。受注後に店内写真へ差し替え | 表示の安定・ライセンス管理のため |
| ヒーロー | 3案を作って比較する。WebGLを使うのは1案だけ。動画は使わない | 軽さを優先。重さの上限を決めて守る |

### 工程2：HTML/CSSでトップページを作る

準備

* Claude Code に入れるもの
  * frontend-design（スキル）
  * UI UX Pro Max（スキル）
  * Playwright（MCP）：スクリーンショットと検品に使う
  * GSAP MCP は入れなくてよい。GSAP本体（無料）をファイルで読み込めば、Claude はそのまま書ける。
* Git で管理し、区切りごとにコミットする。
* 指示の頭に毎回書く：「DESIGN.md と CONTENTS.md を最優先。スキルの提案と矛盾したら仕様書に従う」

手順

1. ヒーローだけを3案作る（「3. ヒーロー3案」参照）。Claude の最上位モデルを使う。
2. Playwright で 375px／768px／1280px のスクリーンショットを撮り、Lighthouse の数値と一緒に比べて1案に決める。
3. 決めた案で全セクションを作る（CONTENTS.md の 1〜13）。
4. 画像：Pexels・Pixabay から手動でダウンロード → WebP（長辺1600px程度、スマホ用に小さいサイズも用意）→ /images/ に置く。出典とライセンスを credits.md にメモする。
5. 営業中バッジを JavaScript で作る（Asia/Tokyo の曜日と時刻で判定）。

ファイル構成：index.html ／ assets/css/style.css ／ assets/js/main.js ／ images/

### 工程3：WordPress化（自作テーマ）

* Local で WordPress を作る。PHP 8.0以上・WordPress 6.9以上（Novamira の動作条件）。
* AI に HTML をクラシックテーマへ変換させる。

```
hoshizora-records/
  style.css        … テーマ名などの情報
  functions.php    … CSS・JS・Google Fontsの読み込み、メニュー、アイキャッチ
  header.php / footer.php
  front-page.php   … トップページ
  index.php / page.php / single.php / archive.php
  assets/          … css・js
```

* 画像をメディアライブラリに登録し、URLを差し替える。
* テーマを zip にして「外観 → テーマ → 新規追加 → テーマのアップロード」から入れ、有効化する。
* 設定：パーマリンクは「投稿名」。表示設定の「検索エンジンがサイトをインデックスしないようにする」にチェック（デモ中のnoindex）。

### 工程4：AIで WordPress を操作する（Novamira）

順番を守る。

1. バックアップを設定する（UpdraftPlus 無料版、または Local の Export）。
2. Novamira を入れて Claude Code と接続する。本番サイトにはつながない。
3. テーマのコード修正、テキストと画像の差し替え。
4. 区切りごとにバックアップと Git コミットを取る。

注意：Novamira は PHP の実行・データベースの変更・ファイルの編集までできる。指示は「何を・どのファイルで」まで具体的に書き、作業後に変更点を確認する。使わないときは AI 機能をオフにする。

### 工程5：動的なサイト化

* 入荷情報
  * 「投稿」で管理する。カテゴリ＝ジャンル。価格・タグはカスタムフィールド（ACF 無料版）。
  * トップは最新6件を自動表示する（WP_Query）。
  * デモ記事を6件登録する（タイトルに【デモ】）。
* お問い合わせ（Contact Form 7）
  * 項目：種別（在庫の確認／買取の相談／その他）、お名前、メール、電話（任意）、内容、プライバシーポリシーへの同意
  * /contact/?type=buyback で「買取の相談」が選ばれた状態にする（CF7 の default:get）
  * スパム対策（CF7 の reCAPTCHA 連携など）、自動返信メール、送信内容の保存（Flamingo 無料）
  * Local ではメールが外に出ない。Local に入っている Mailpit で、届いたかを確認する
* Gutenberg化
  * 店主さんが自分で更新する所（ABOUT本文、お知らせ、営業時間など）をブロックで編集できるようにする。
  * セクションをブロックパターン（patterns/ フォルダ）にする。クラス名 hr- を保ち、デザインが崩れないようにする。

## 3. ヒーロー3案

### 全案に共通の条件

* 375×667 のスマホ画面で、キャッチ・営業中バッジ（定休日・営業時間外のときだけ出る）・「行き方を見る」ボタンが最初に見える
* 写真がなくても成り立つ（デモ段階は店内写真がないため）
* 重さの上限：ヒーローの画像は合計200KB以内、ヒーロー用のJSは50KB以内（gzip）、動画は使わない
* 動きは初回だけで、2秒以内に止まる（案Bの星の瞬き・案Cの波紋は例外）。回転・パララックスはなし
* 動きを減らす設定（prefers-reduced-motion: reduce）のときは、最初から完成した状態で止まって表示する
* 目標：Lighthouse モバイルの Performance 90以上、LCP 2.5秒以内、CLS 0.1以下

### 案A：縦書きのキャッチ（文字が主役）

* 生成りの面に、明朝の縦書き（writing-mode: vertical-rl）で大きく「ほしい一枚に、ここで出会う。」
* 文字が一文字ずつ下から浮かぶ（GSAP、約1秒、初回のみ）
* 隅にレコード盤の同心円（細い線のSVG）が、線を描くように現れる。回転はしない
* 重さ：GSAP本体の約25KBだけ。写真はなし、または右側に1枚

### 案B：夜の紺と星（色が主役）

* 紺の面に生成りの明朝キャッチ。金の星（✦）3つがCSSだけでゆっくり瞬く
* 写真は窓のような枠に1枚（4:5）。デモ段階はフリー素材
* 重さ：JSは0KB（CSSアニメーションのみ）
* DESIGN.md の例外（ヒーローの紺背景）を使う

### 案C：溝のゆらぎ（軽量WebGL）

* 紺から生成りへのグラデーションに、レコードの溝のような同心円の波紋がゆっくり広がる
* three.js は使わず、素の WebGL のシェーダー1枚（数KB）で作る
* ページの表示が終わってから動かし始める。画面外では止める。WebGL が使えない端末・動きを減らす設定のときは静止したSVGに切り替える
* 動き続ける唯一の案なので、重さと電池の減りを実際に測ってから判断する

（第1ラウンドの案A〜Cは 2026-11-07 に不採用。理由：画面の半分以上が空いていた／結局「左に文字・右に空の写真枠」の定番に戻った／グレーのグラデーションがくすんで、生成り・紺・朱のどの色でもなかった／同心円が射撃の的に見えた／画面いっぱいの見せ場がなかった）

## 4. ヒーロー 第2ラウンド（WebGL 3案）

### 全案に共通の条件

* 3案とも WebGL の背景を画面いっぱい（ヘッダーの下からヒーローの下端まで）に使う。かっこよさと、ページを開いたときの軽さを両立する
* 375×667 のスマホ画面で、キャッチ・営業中バッジ・「行き方を見る」ボタンが最初に見える
* 軽さのルール（Design.md 5章「ヒーロー」）
  * 素の WebGL1。全画面の三角形1つ＋フラグメントシェーダー1枚。ライブラリなし（three.js も GSAP も使わない）
  * ヒーロー用の JS は圧縮前で 8KB 以内。画像・動画・追加フォントなし
  * 最初は CSS のグラデーションで表示して文字をすぐ出す。WebGL は load の後に始めて、0.6秒ほどでふわっと重ねる
  * devicePixelRatio は最大 1.5。スマホは描画サイズ 0.75 倍・30fps まで
  * 画面外とタブが裏のときは止める
  * 動きを減らす設定・WebGL 非対応・データセーバーのときは CSS の背景のまま止める
* 色は Design.md のパレットだけ（紺 #1E2A44、朱 #9A3324、金 #D4A73A、生成り #F6F1E7）。くすんだグレーにしない
* 文字の後ろは明るさの変化を抑え、コントラスト 4.5:1 以上を常に保つ
* 前回の反省：空の写真枠を置かない。左右2等分にしない。画面の大半を空けたままにしない
* 目標：Lighthouse モバイルの Performance 95以上、LCP 2.0秒以内、TBT 50ms以下、CLS 0.1以下。CPU を4倍遅くした状態でも動きがカクつかない

### 案D：溝の光沢（レコード盤に光が走る）

* 紺の面いっぱいに、巨大なレコード盤の一部（中心は画面の右外）。髪の毛ほどの細い溝がびっしり並ぶ
* 盤は回らない。光のほうが動く。照明が盤に当たったときの金色の光沢の帯が、ゆっくり盤面をなでる
* マウス・指の位置で光沢の向きが少し変わる。触っていないときは、ゆっくり自動で動く
* キャッチは左側に生成りの明朝で大きく（縦書きでもよい）

### 案E：朱と紺のにじみ（紙にインクが広がる）

* 生成りの紙（シェーダーで細かい紙の繊維の粒を描く）の上に、朱と紺のインクがゆっくりにじんで混ざり合う
* インクは画面の片側（右上か右下）に寄せる。文字の周りは紙のまま残して読みやすくする
* 大正期の木版ポスターや染め物のような、温かくて少しレトロな印象。キャッチは墨色の明朝

### 案F：星を探す夜（「星を探すように一枚を選ぶ」）

* 紺の夜空に、シェーダーで描いた細かい星がまたたく。ときどき流れ星が1本
* マウス・指の周り（スマホではゆっくり自動で動く）に、朱色のあたたかい光がにじむ。その中だけ星が金色に明るくなる。暗い棚から一枚を探す感覚
* Design.md のコンセプト「大正浪漫の2階で、星を探すように一枚を選ぶ」をそのまま絵にする
* キャッチは生成りの明朝

### 決定（2026-11-07）

* 案D「溝の光沢」に決定。案E・Fは不採用
* 次はキャッチの見せ方とアニメーションを比べる。hero-d.html の URL の末尾（?anim=1〜4）で切り替えて見比べる

## 5. ヒーロー 第3ラウンド（文字・WebGL・スクロール）

* 第2ラウンドのキャッチアニメーション4案（光がなでる／盤から光が届く／ピントが合う／一文字ずつ浮かぶ）は不採用（2026-11-07）。理由：背景を変えただけに見えてAIっぽい。文字が小さく、迫力がない
* 方針：案Dの世界観（紺・溝・金の光沢）はそのまま。文字を画面いっぱいに大きくして、文字・WebGL・スクロールを1つの演出にする
* 3案（hero-g／hero-h／hero-i）を作り、書体も切り替えて比べる（?font=1 Zen Antique／2 Kaisei Tokumin／3 Dela Gothic One）
* 目標：Lighthouse モバイル Performance 90以上、LCP 2.5秒以内、CLS 0.1以下

### 案G：盤面に刻む

* 画面いっぱいの巨大なキャッチを、レコード盤に刻まれた文字として見せる。キャッチを 2D canvas で描いてシェーダーに渡し、文字の中にも溝が走り、金色の光沢が溝と文字の上を一緒に通る
* 登場：光の帯が通ったところから、刻まれた文字が浮かび上がる
* スクロール：盤面に近づいていくように溝と文字が拡大して、光が強まりながら次のセクションへ抜ける

### 案H：針が落ちる

* 最初に金色の細い線（レコードの針）がすっと下りて盤面に触れる。そこから音の波形のような線が横に走り、その波に乗ってキャッチが大きく現れる
* スクロール：巨大なキャッチの1行目と2行目が、スクロールに合わせて逆向きに横へ流れる。波形の線はそのまま下のセクションの区切り線につながる

### 案I：エサ箱をめくる

* レコード店の「エサ箱」（レコードを立てて並べた箱）をめくる感覚。キャッチの1文字ずつを正方形のジャケットのような札に載せ、札がパタパタとめくれて文字が並ぶ
* スクロール：札が1枚ずつ奥へ倒れていき、最後の1枚の向こうから次のセクション（新着入荷）が現れる
* 背景は案Dの溝と光沢をそのまま使う

## 6. ヒーロー 案J「波打つ溝」（2026-11-08）

* 第3ラウンド（案G・H・I）のあと、方向を大きく変更。背景を白にして、黒い細い線の同心円（音の波形のようなギザギザ）にし、カーソルが触れると波打つようにした
* 試作：hero-lab/hero-j.html（ヘッダー付き、ボタンなし）
* 切り替え：?bg=kinari（生成り）／?ink=sumi（墨色の線）／?copy=2（「欲しい1枚に」）／?min=1（キャッチだけ）
* 未決定：背景の色（白／生成り）、キャッチの文言
* 次：細部を調整して決定 → index.html のヒーローを案Jに置き換え → プロンプト4（中身）へ。サイト全体の背景を白に合わせるかもあわせて決める
* 決定（2026-11-08）：背景は白、キャッチは「欲しい1枚に／ここで出会う。」。ヘッダーのメニューは ホーム・はじめての方へ・入荷情報・営業日・アクセス・お問い合わせ。ロゴの横は星ではなく猫とレコードのアイコン（仮）

## 7. HTML の仕上げの進め方（2026-11-13 決定）

1. 大枠を作り終える：入荷情報の修正 → お問い合わせ・送信完了、プライバシーポリシー、404
2. 共通の演出を一度に入れる → 2026-11-13 に A・B・C を試したが、すべて不採用（元に戻した）。演出は「1ページずつ仕上げる」段階で、ページを見ながら必要なところだけ考える
   * A. ジャケットからレコードが出てくる：入荷カードにマウスを乗せると、ジャケットの横からレコード盤がすっと出てくる（PCのみ・CSS中心）
   * B. リングが背景でつながる：ヒーローのリングがスクロールに合わせて薄く・大きくなりながら、下のセクションの背景にうっすら残る（PCのみ）
   * C. 紙の質感：生成りの面にごく薄い紙のざらつきを重ねる（動かない・全画面幅）
   * 見せ場は2〜3か所に絞る。背景全体が常に動き続ける演出は入れない
3. 1ページずつ仕上げる：トップ → 入荷情報 → はじめての方へ → 買取 → アクセス → 営業日 → お問い合わせ → その他。そのページならではの見せ場と細かい見た目を整える
4. サイト全体の検品：全ページをチェックリストと Lighthouse で確認（スマホの Performance 90以上を守る）、スマホ実機でも確認
5. WordPress 化へ（工程3〜5）
