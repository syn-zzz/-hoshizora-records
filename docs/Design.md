# Visual Design System (DESIGN.md)：ほしぞらレコード

本ファイルは、AIエージェントがUIコード（HTML, CSS, WordPressブロック, など）を生成する際に参照するデザイン仕様書です。UIを構築する際は、必ずこのルールに従ってください。

対象サイト：ほしぞらレコード（夢見市・夢見通りの中古レコード店）リニューアル提案用デモ
実装環境：HTML/CSSで作成 → WordPressの自作クラシックテーマに変換（ヘッダー・フッターはテーマのPHP、店主が更新する本文はGutenbergのブロック）。有料テーマ・有料プラグインは使わない

## 1. トーン＆マナー

* ブランドイメージ: 大正浪漫の街並みになじむ、あたたかくて気軽なレトロ。古道具屋風ではなく「今の中古レコード店」

* モチーフ: 白い紙、看板の朱色、生成りの紙、レコードの溝（細い線の同心円）。2026-11-08 に白を基調に変更

* 避けるもの: 黒×ネオンのクラブ風、金の装飾枠、和柄の敷き詰め、回転し続けるレコードのアニメーション

## 3. タイポグラフィ (Typography)

* 見出し 1 (h1): 1.75rem (28px) → PCで 2.25rem (36px), line-height: 1.4, 太字
* 見出し 2 (h2): 1.5rem (24px) → PCで 2rem (32px), line-height: 1.5, 太字, letter-spacing: 0.06em
* 見出し 3 (h3): 1.1875rem (19px) → PCで 1.375rem (22px), line-height: 1.5
* 見出しの改行: 見出しは単語や文節の途中で改行しない。短い見出し（「見るだけでも、ふらっとどうぞ。」など）はスマホでも1行に収める（文字サイズを画面幅に合わせて少し小さくしてよい。2026-11-08）

* 価格: font-variant-numeric: tabular-nums
* セクション見出しの型: 英字ラベル（例「✦ NEW ARRIVALS」13px・ゴシック・Primary・letter-spacing 0.2em・aria-hidden="true"）の下に日本語の h2

## 5. コンポーネントスタイル (Components)

* ヒーロー (Hero) ※案J「波打つ溝」で進める（2026-11-08）。試作は hero-lab/hero-j.html:
   * 背景：白（#FFFFFF）に決定（2026-11-08）。このページの「生成り」を白に置き換える
   * リング：黒い細い線（約70本）の同心円。音の波形のようなギザギザがあり、隣り合う線は似た形で束になって見える。何もしなくても、ごくゆっくり形が変わる。回転はしない
   * カーソル（指）が触れると、触れた所の線が波打つ。動かす速さで揺れが大きくなり、止めるとゆっくり戻る
   * 配置：PCは文字が左・リングが右。スマホは文字の後ろにリングを重ねる（2026-11-08 決定）
   * キャッチ：朱（Primary）の明朝で大きく（PCで画面幅の約6.4%、最大7.5rem）。2行目は少し右に下げる。開いたときに下からすっと現れる（CSSだけ・1回・1秒以内）
   * ヒーローには「行き方を見る」「新着入荷を見る」のボタンを置かない（2026-11-08 決定）。行き方へはナビとスマホ固定バーから行ける
   * 営業中バッジと説明文は残す。線の上でも読めるように、文字の周りだけ背景色でふちどる（text-shadow）
   * ヘッダー：土台のヘッダーをそのまま使い、背景だけページ色（白）に合わせる
   * 軽さ：ライブラリなし。WebGL の LINES で1回に描く。JSは圧縮前で約6KB。読み込み中は CSS の薄い同心円を代わりに出す。画面外・タブが裏のときは止める。スマホは30fps・描画解像度1.5倍まで
   * prefers-reduced-motion：1枚描いて止める。WebGL 非対応：CSS の同心円のまま
   * キャッチの文言：「欲しい1枚に」「ここで出会う。」の2行に決定（2026-11-08）
   * スクロール演出は PC（960px 以上）だけ。スマホ・タブレット（959px 以下）ではスクロールに連動する動き（ふわっと表示、見出しの時間差、キャッチのスクロール退場）を入れず、最初から完成状態で表示する（2026-11-08 決定）。リングを指でなぞると波打つ動きはスマホでも残す
   * スクロール演出（第3ラウンドから引き継ぐ。ヒーローだけでなくセクションのつなぎにも使ってよい）:
      * スクロールの速さや量を乗っ取らない（スクロールを遅くする・止めるライブラリは使わない）
      * CSS のスクロール連動アニメーション（animation-timeline: scroll() / view()）を優先し、対応していないブラウザでは完成状態で表示（@supports で切り替え）。足りない所だけ IntersectionObserver と requestAnimationFrame の小さな JS
      * 動かすのは transform と opacity だけ（CLS 0.1 以下）
* 下層ページの見出し (Page Header) ※2026-11-08 追加:

## 7. アクセシビリティ (Accessibility)

* WCAG 2.2 AA を目標にする。
* すべてのテキスト（特に警告やエラーメッセージ）は、背景色とのコントラスト比を 4.5:1 以上にすること。入力欄の枠など文字以外の部品は 3:1 以上。
* 画像には必ず alt 属性を記述すること。写っているものを具体的に書き（例「ロックとソウルのレコードが並ぶ店内の棚」）、装飾画像は alt="" にする。
* 色だけで情報を伝えない（営業中バッジ、エラー、必須表示は必ず文字付き）。
* キーボードだけで全ページを操作できること。フォーカス表示を消さない。
* 見出しは h1 → h2 → h3 の順を飛ばさない。h1 は1ページに1つ。
* 地図の埋め込みには住所を文字で併記する。
* prefers-reduced-motion: reduce のときはアニメーションと transition をすべて止める（ヒーローも完成した状態の静止表示にする）。
